About ORZEN

“What if the planner did more of the planning?” I wrote that question into ORZEN’s About page because it was the part of using a planner that kept bothering me. I could already put my commitments on a timeline. Move an appointment, though, and suddenly three other activities need another look. ORZEN began as an attempt to give some of that work back to the planner.

I wanted to be able to open it for an ordinary day without learning an elaborate system. The details should be there when I need to inspect a choice. If I want to take over and move something myself, I should be able to do that too.

Inside the project

A conversation and a set of rules

Zen is the part a person talks to. Behind that conversation, PELIOS reasons about the activity, its constraints, and what the planner has permission to change. A deterministic scheduler checks whether a proposed placement fits. I can inspect an activity’s time, duration, flexibility and obligation.

Those last two properties answer different questions. An activity can have a flexible start time and still have to happen today. If moving it would carry it beyond its allowed window, it needs another decision.

When planning hands back control

The app’s About screen puts it simply: “Automation should know when to stop.” Attention collects unresolved items, including displaced commitments, missing information and activities without a feasible slot. Seeing a problem waiting for me is more helpful than discovering later that an obligation disappeared.

What I can open today

The local prototype has a timeline, fixed and flexible activities, conflict detection, saved conversations for individual days, and an Attention view. The screenshots show the actual Expo web interface with a fictional schedule. The desktop image was captured without a live assistant connection.

A manifesto that can change

I built ORZEN with Zen, my AI collaborator. Trying real planning problems together showed me where the early rules were too simple. The notes inside the app keep that history alongside the design principles.

I’m interested in a future Day Changed flow, reliable conversational changes to existing activities, replanning across days, travel, routines and calendar integrations. Those are directions I want to explore. For now, one changed appointment is enough to test whether the system can explain its decision.
