Inside the project

A job you can see

A task can sit in a queue, an agent can be on its way, and a worker can be running. Those are three moments. In Studio I wanted to be able to look at the office and tell them apart.

Arrival is part of the workflow

The Godot client shows a solar system, a colony, and its workstations. When a job is assigned, its agent travels to the assigned station. The recorded event checks place the worker start after arrival. A blocked job has no worker start in the supplied regression evidence.

Following one job

The character, pad, and job log give me three views of the same handoff. They also make failures easier to discuss. I can ask whether the agent reached the station before asking whether its tool produced anything.

What the release evidence covers

The supplied v0.13.1 evidence includes rendered colony views, tests of job ordering, and a run of the creative QA tool on an existing video. Conversation checks used test fixtures. The recorded suite did not run a live language model or establish Mac acceptance.

The next question

I want to follow a real local-model job through the same steps on my Mac and compare its log with what I see on screen. That would test the link between the interface and the work it represents.
